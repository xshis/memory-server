# personal-kb 安装与使用手册

> 适用范围：当前仓库的脚本布局（见第 2 节）。
> 目标：从零安装到日常使用，说明每个脚本的用途、前置条件和排错方式。
> 文中 `/path/to/personal-kb` 是项目目录占位符，请替换为实际路径。

---

## 0. 最短路径

**macOS**

1. 双击 `一键启动.command`。
2. 按提示授权、选择索引范围。
3. 菜单栏出现 `KB` 后，打开 `http://127.0.0.1:8770/`。

**终端**

```bash
cd /path/to/personal-kb
bash install.sh
.venv/bin/python -m kb setup --start
```

**Windows**

```powershell
cd personal-kb
powershell -ExecutionPolicy Bypass -File install.ps1
start.bat
```

只检查环境：

```bash
.venv/bin/python -m kb setup --check
```

## 1. 前置条件

### 1.1 系统

| 项目 | 要求 |
|---|---|
| macOS | 12 及以上；菜单栏托盘仅 macOS 可用 |
| Windows | Windows 10 / 11 x64 |
| Linux | 可运行 Python 和命令行的环境；没有菜单栏托盘 |
| 硬件 | 最低 8GB 内存、10GB 空闲磁盘；推荐 16GB 内存、SSD |

### 1.2 Python

- 需要 **Python 3.10 及以上**，推荐 3.12。
- `install.sh` 会自动在 `python3.13 / 3.12 / 3.11 / 3.10 / python3` 中查找可用版本。
- 没有 Python 时：
  - macOS：`brew install python@3.12`，或从 <https://www.python.org/downloads/> 安装。
  - Windows：从 python.org 安装，勾选 “Add Python to PATH”。

> 不需要管理员权限，也不需要 `sudo`。所有依赖装在项目内的 `.venv`。

### 1.3 macOS 权限（TCC）

如果项目放在 `~/Documents`、`~/Desktop`、`~/Downloads` 等受 macOS 隐私保护（TCC）的目录下，终端访问会被拦截。首次运行前建议先确认：

- 系统设置 → 隐私与安全性 → **完全磁盘访问权限**：给运行安装/服务的终端（Terminal / iTerm 等）打开开关；如果通过 AI 客户端启动，也给它授权。
- 或者 系统设置 → 隐私与安全性 → **文件与文件夹**：允许终端访问“文稿/桌面/下载”。

授权后必须**完全退出并重开终端 / AI 客户端**，只关窗口不算。

`kb setup` 和 `一键启动.command` 会检测这些路径；被拒绝时会询问并直接打开对应设置页：

- 完全磁盘访问：`x-apple.systempreferences:com.apple.preference.security?Privacy_AllFiles`
- 文件与文件夹：`x-apple.systempreferences:com.apple.preference.security?Privacy_FilesAndFolders`

验证命令：

```bash
cd /path/to/personal-kb
head -c 20 .venv/pyvenv.cfg
.venv/bin/python -c "print('python ok')"
```

### 1.4 网络

| 场景 | 要求 |
|---|---|
| 首次安装 | 能访问 PyPI（`pip install`）；公司网络需要配置代理或 pip 镜像 |
| 飞书机器人 | 能出站访问 `open.feishu.cn` 的 HTTPS/WSS 443；不需要公网 IP、域名或入站端口 |
| 豆包工作 | 只访问本地 `127.0.0.1:8766`，不需要外网入站 |
| 日常搜索 | 完全本地，不依赖网络 |
| 本机代理（ClashX/Surge 等） | **必须放行 127.0.0.1 直连**：增强模式/TUN 若拦截回环地址，浏览器打不开脑图、MCP 客户端连不上，表现是"连接超时"而终端 curl 正常；给 127.0.0.1 加绕过规则或临时退出代理 |

嵌入模型下载（首次 `kb index` 后自动触发一次，约 100MB）：走 HuggingFace，不通会自动走镜像源；仍失败设 `HF_ENDPOINT=https://hf-mirror.com` 后重试。分享包预置模型可跳过下载（见第 3 节）。

### 1.5 可选的外部接入

**飞书机器人**（可选）：

1. 在飞书开放平台创建企业自建应用，添加“机器人”能力。
2. 权限至少包含：接收消息、以应用身份发消息、私聊消息、群 @ 消息、文件上传/发送。
3. 事件订阅选择**长连接**，订阅 `im.message.receive_v1`。
4. 发布应用并等管理员审核。
5. 把 App ID / App Secret 填到 `config/feishu.json`，白名单填自己的 `open_id`。

详细步骤见 `docs/飞书接入手册.md`。`kb setup` 会校验配置、白名单和机器人能力。

**豆包工作**（可选）：

1. 安装豆包工作电脑版（`/Applications/DoubaoWork.app`）。
2. 服务启动后，在豆包工作里添加连接器：
   - 插件 · 技能 → 管理 → 连接器 → 添加 → 新建自定义连接器
   - 名称：`personal-kb`
   - 传输类型：`HTTP`
   - 服务器 URL：`http://127.0.0.1:8766/mcp`
   - Headers 留空，保存并打开开关
3. 首次在豆包任务里调用时，按提示允许“本地电脑”访问。

`kb setup` 会检测豆包是否安装、是否已有 `personal-kb` 连接器；没有时打印上面的步骤并询问是否打开豆包。

### 1.6 端口与目录

- 默认端口：3D 脑图 `8770`，MCP `8766`；默认只绑定 `127.0.0.1`。
- 端口被占用时先运行 `kb stop --force`，或修改 `config/config.json` 里的端口。
- 项目目录可以整体移动，但移动后 `.venv` 里的路径会失效：删除 `.venv`，重新运行 `bash install.sh`。
- 不要用 `sudo` 运行安装或服务。

### 1.7 可选能力的前置条件

- **语义混合检索**（默认安装）：依赖 `fastembed`（ONNX 本地推理，不联网可用）。嵌入模型 `bge-small-zh-v1.5` 缓存在 `~/.cache/fastembed`（可用 config 的 `models.local.embed_cache_dir` 改位置）；不需要语义检索时用 `KB_WITH_EMBED=0` 跳过安装。索引建立后**自动**为新文件补算向量（见 4.6）。
- **图片整理**：需要 OpenCV（约 50MB）；安装 `pip install -e ".[vision]"`，或在 `kb setup` 中选安装。
- **本地模型问答**：需要 Ollama。安装脚本最后会让选择模型：
  - `qwen2.5:3b`（推荐，约 1.9GB，平衡）、`qwen2.5:1.5b`（更快，约 1GB，质量略低）、`qwen2.5:7b`（更强，约 4.7GB，CPU 明显更慢）
  - 100Mbps 下载约 3~6 分钟，慢网 10~30 分钟；效果是离线问答/总结，资料不出本机
  - 非交互安装可设 `KB_OLLAMA_MODEL` 指定模型，`KB_WITH_OLLAMA=0` 跳过；也可稍后运行 `kb model install --name ...`
  - 已把 `num_ctx/num_predict/context_chars/max_sources` 调小以降低 CPU 等待；CPU 也能跑但较慢
- 两者都不装时，搜索、整理（按类型/日期/内容）、摘录式问答仍然可用。

## 2. 脚本文件清单

用户入口保持在项目根目录，方便双击；开发者脚本放在 `scripts/`。

| 文件 | 平台 | 用途 | 何时用 |
|---|---|---|---|
| `一键安装.command` | macOS | 双击安装环境，装完暂停 | 第一次安装 |
| `一键启动.command` | macOS | 缺环境先安装；环境/权限/索引引导；启动服务；后台拉起菜单栏 | 日常启动 |
| `一键关闭.command` | macOS | 停止网页、MCP、监听、飞书，并退出菜单栏 | 日常关闭 |
| `install.sh` | macOS / Linux | 命令行安装：找 Python、建 `.venv`、装依赖、自检 | 终端安装或升级 |
| `install.ps1` | Windows | PowerShell 安装 | Windows 首次安装 |
| `一键安装.bat` | Windows | 双击安装 | Windows 首次安装 |
| `start.sh` | macOS / Linux | 终端启动 `kb start`（守护模式） | 不想用托盘时 |
| `start.bat` | Windows | 终端启动 `kb start` | Windows 日常启动 |
| `scripts/scan-secrets.sh` | macOS / Linux | 开发者用：扫描项目里的密钥/个人路径 | 打包分享前 |
| `scripts/scan-secrets.ps1` | Windows | 同上 | 打包分享前 |

命令入口（不是文件）：

| 命令 | 作用 |
|---|---|
| `kb setup` | 环境检测、权限引导、飞书/豆包接入引导、索引引导、启动 |
| `kb setup --check` | 只检测，不修改、不弹窗、不启动 |
| `kb setup --check --json` | 输出 JSON，供脚本/监控使用 |
| `kb tray` | 启动 macOS 菜单栏 |
| `kb tray --check` | 只检查托盘依赖和服务状态 |
| `kb start` / `kb stop` | 启动/停止守护服务 |
| `kb model status` | 查看 Ollama/模型状态 |
| `kb model install --name qwen2.5:3b` | 安装 Ollama（如需要）并下载模型 |
| `kb model enable` / `disable` | 启用/关闭本地模型问答 |
| `kb map --open` | 启动 3D 知识库脑图（默认 127.0.0.1:8770） |
| `kb logs [name]` | 查看日志 |

`kb setup` 可选参数：

- `--with-vision`：安装 OpenCV 图片整理依赖。
- `--with-ollama`：安装 Ollama（如需要）、下载并启用本地模型。
- `--ollama-model qwen2.5:3b`：指定模型。
- `--no-ollama`：关闭本地模型问答，恢复摘录式匹配。

## 3. 安装

### 3.1 macOS 一键安装

1. 双击 `一键安装.command`。
2. 终端会运行 `install.sh`：查找 Python、创建 `.venv`、安装依赖（含菜单栏 `rumps`）、运行 `kb doctor`。
3. 结束后按任意键关闭窗口。

> 这一步只安装环境，不启动服务、不建索引。

### 3.2 macOS 终端安装

```bash
cd /path/to/personal-kb
bash install.sh
source .venv/bin/activate
```

可选依赖：

```bash
# PDF / Word / Excel / PPT 正文提取
KB_WITH_DOCS=1 bash install.sh

# 飞书机器人
KB_WITH_FEISHU=1 bash install.sh
```

### 3.3 Windows 安装

```powershell
cd personal-kb
powershell -ExecutionPolicy Bypass -File install.ps1
```

或双击 `一键安装.bat`。需要飞书时先设置：

```powershell
$env:KB_WITH_FEISHU="1"
powershell -ExecutionPolicy Bypass -File install.ps1
```

Windows 没有菜单栏托盘，日常用 `start.bat` / `kb start` / `kb stop`。

### 3.4 安装做了什么

- 在项目内创建 `.venv`，不会污染系统 Python。
- 安装 `mcp` 等运行依赖；macOS 额外安装 `rumps`。
- 按环境变量安装可选的文档解析、飞书依赖。
- 运行 `kb doctor` 检查 Python、SQLite FTS5、数据目录、端口、可选依赖。
- 不启动服务，不修改索引数据。

### 3.5 升级

重新运行安装脚本即可：

```bash
bash install.sh
```

数据库结构会在启动时自动补齐，不需要手动迁移。

### 3.6 卸载

```bash
kb stop
# macOS 另可在菜单栏点“退出（停止服务）”
```

然后删除整个 `personal-kb` 目录。程序没有注册系统服务、开机项或全局命令；删除目录即可。
如果还要保留索引，先运行 `kb export --mode migrate -o dist/migrate.zip`。

## 4. 首次启动与索引

### 4.1 macOS 一键启动（推荐）

双击 `一键启动.command`，依次执行：

1. 缺环境时先安装。
2. 检查系统权限；被拒绝时询问并打开对应设置页。
3. 检查豆包工作是否安装、是否已有 `personal-kb` 连接器。
4. 检查飞书配置、白名单和机器人能力。
5. 没有索引范围时进入选择菜单；索引为空时询问是否建立。
6. 启动 3D 脑图、MCP、监听、飞书机器人。
7. 在菜单栏显示 `KB ●` 图标，关闭终端窗口也会继续运行。

### 4.2 终端启动

```bash
cd /path/to/personal-kb
.venv/bin/python -m kb setup --start
# 或者
bash start.sh
```

`kb setup --start` 会先检测再启动；`start.sh` 直接进入 `kb start` 守护模式。
首次没有索引范围时，`kb start` 会提示选择文件夹/盘符。

### 4.3 权限被拒绝时

如果看到 `Operation not permitted`、`无法读取 .venv/pyvenv.cfg`，或索引时大量目录被跳过：

1. 运行 `kb setup`，按提示打开“完全磁盘访问权限/文件与文件夹”。
2. 给终端和启动本程序的 AI 客户端打开开关。
3. 完全退出并重开终端 / AI 客户端。
4. 重新运行 `kb setup --check` 验证。

### 4.4 选择索引范围

第一次运行 `kb index`、`kb start`、`kb feishu` 时会自动弹出选择菜单；也可以手动：

```bash
kb scope                       # 交互菜单
kb scope --add ~/Documents     # 添加文件夹
kb scope --add "D:\资料"        # Windows
kb scope --remove ~/Downloads
kb scope --list
kb scope --clear
```

默认排除系统目录、缓存、`.venv`、`node_modules`、密钥文件等；超过 `max_file_size_mb`（默认 20MB）的文件只索引文件名，不读正文。

### 4.5 建立索引

```bash
kb index              # 增量建立/更新
kb index --full       # 忽略缓存全量重建
kb status             # 查看文件数、已提取正文、错误数
```

启动服务后 `watch` 默认用文件事件监听（macOS FSEvents / Windows / Linux），只索引新增、修改、删除的文件，不再定时遍历全盘。也可以用 `--no-events` 退回定时扫描，或 `--daily 10:00` 固定时间扫描（关机/睡眠错过不补跑）。服务停机期间的变化不会自动补，启动后点一次页面“更新索引”或运行 `kb index` 即可。首次全盘索引可能较慢，建议先选一个较小的文件夹试用。同一时间只允许一个 `kb index` 进程（`data/index.lock`），重复启动会直接跳过；`kb start` 默认带 `monitor`，每 30 分钟自检索引、服务、磁盘、权限和索引锁，结果写入 `logs/selfcheck.log`。

### 4.6 语义向量与自动补算

索引建立后会自动给文件正文计算语义向量（本地 fastembed，资料不出机），用于"按意思搜索"和脑图里的相似文件/语义连线。

- **全自动，无需手动**：`kb index` 完成、watch 监听到新文件后都会自动补算；后台进程限 2 核运行（`nice` 降级 + `OMP_NUM_THREADS=2`），两次自动补算至少间隔 15 分钟（缺口 ≥3000 立即补）。
- **看进度**：脑图顶栏"语义嵌入 xx%"；`logs/auto-embed.log` 记每次触发；`kb embed --stats` 查精确统计。
- **手动补算**：`kb embed`（幂等、断点续跑，随时可重复执行）。
- **总开关**：环境变量 `KB_AUTO_EMBED=0` 或 config 里 `embed.auto: false`；测试环境自动关闭。
- **换机器/重装**：向量存在 `data/kb.db` 的 `file_embeddings` 表里随库走，不用重算；删除 `.venv` 重装不影响。

## 5. 日常使用

### 5.1 3D 脑图

```text
http://127.0.0.1:8770/
```

左侧是知识库助手，中间是星空脑图；搜索、提问、推荐清理和整理都在这里。默认只绑定本地。

### 5.2 菜单栏（macOS）

启动方式：`kb tray`，或双击 `一键启动.command` 自动拉起。

菜单项：

- 运行状态
- 打开 3D 脑图（8770，未运行会自动拉起）
- 复制 MCP 地址
- 环境与接入检查…（打开 Terminal 运行 `kb setup`）
- 重新索引
- 查看日志（map / mcp / watch / feishu / tray）
- 打开项目目录
- 启动服务 / 停止服务
- 退出（停止服务）

### 5.3 常用命令

```bash
kb search "报销"
kb search "报价单" --ext xlsx
kb get /path/to/file --max-chars 8000
kb ls /path/to/folder --depth 2
kb summarize /path/to/folder
kb ask "报销流程是什么"
kb watch --events           # 默认：文件事件监听，只索引变动的文件
kb watch --no-events --interval 3600   # 退回定时扫描（每小时）
kb watch --daily 10:00      # 固定时间扫描；关机/睡眠错过不补跑
kb index                    # 全量增量索引；同一时间只允许一个 kb index（data/index.lock）
kb scan-junk                # 扫描电脑可清理文件（下载/临时/缓存目录，通用规则，只报告）
kb scan-junk ~/Downloads --trash --yes   # 把白名单类别（临时/空/旧日志/重复/旧备份）移入废纸篓，可恢复
# 规则跨 Windows/macOS/Linux：.DS_Store/Thumbs.db/Office~$锁/.part/.crdownload/.partial/.crswap、
# .bak/.old 超 30 天、缓存目录大文件等；pagefile.sys/hiberfil.sys/$RECYCLE.BIN 等系统对象永不触碰
kb selfcheck                # 立刻跑一次系统自检
kb monitor                  # 常驻自检，默认每 1800 秒一次
kb start                    # 启动 map/mcp/watch/feishu/monitor
kb stop
kb stop --force
kb logs
kb logs map -f
```

### 5.4 MCP

| 地址 | 用途 |
|---|---|
| `http://127.0.0.1:8766/mcp` | MCP 客户端（豆包/机器人） |
| `http://127.0.0.1:8766/` | 浏览器打开会看到“这是 MCP 接口”的提示，正常 |
| `http://127.0.0.1:8770/` | 3D 脑图，不是 MCP |

stdio 模式：

```bash
.venv/bin/python -m kb mcp
```

### 5.5 飞书机器人

配置好 `config/feishu.json` 后，`kb start` 会自动拉起机器人（`--no-feishu` 可关闭）。私聊指令：

```text
找 报价单
发我 报销流程
总结 /path/to/folder
整理 /path/to/folder
确认整理 <计划ID>
撤销 <计划ID>
状态
/whoami
帮助
```

长连接断线会自动重连；日志在 `logs/feishu.log`。

### 5.6 豆包工作

按第 1.5 节添加连接器后，在豆包任务里直接说：

```text
用 personal-kb 搜索报销流程
调用 index_status 查看索引状态
```

连接器只在本地生效，豆包访问的是 `127.0.0.1:8766`。

### 5.7 日志

| 文件 | 内容 |
|---|---|
| `logs/map.log` | 3D 脑图（独立启动时） |
| `logs/mcp.log` | MCP HTTP |
| `logs/watch.log` | 增量扫描 |
| `logs/feishu.log` | 飞书长连接和消息处理 |
| `logs/tray.log` | 菜单栏 |
| `logs/selfcheck.log` | 每 30 分钟系统自检的 JSON 结果（超过 2MB 轮转） |
| `logs/start.log` | `kb start` 守护进程输出（后台启动时） |

```bash
kb logs
kb logs feishu -n 50
kb logs feishu -f
```

## 6. 关闭、重启与开机自启

### 关闭

- macOS：菜单栏 → 退出（停止服务），或双击 `一键关闭.command`。
- 终端：`kb stop`；端口残留用 `kb stop --force`。
- 只停网页但保留其他服务：网页右上角“关闭服务 / 退出”会级联停止同一套服务。

### 重启

```bash
kb stop
kb start
# 或双击 一键启动.command（会自动处理旧实例）
```

### 开机自启（可选）

程序没有内置开机自启。需要时：

1. macOS：系统设置 → 通用 → 登录项，添加 `一键启动.command`。
2. 或自行用 `launchd` 写一个登录时运行 `kb start` 的任务（注意配置 `WorkingDirectory` 和 `KB_HOME`）。

## 7. 故障排查

| 现象 | 处理 |
|---|---|
| `Operation not permitted` / 读不到 `.venv` | 运行 `kb setup` 打开权限设置，给终端 / AI 客户端 完全磁盘访问，重启终端 |
| `kb: command not found` | 先 `source .venv/bin/activate`，或直接用 `.venv/bin/python -m kb ...` |
| 端口被占用 | `kb stop --force`；或 `lsof -nP -iTCP:8766 -sTCP:LISTEN`（Windows：`netstat -ano \| findstr :8766`） |
| 飞书私聊不回 | `kb logs feishu -n 50`；检查白名单、事件订阅“长连接”、机器人权限；确认服务在跑 |
| 飞书日志 `database is locked` | 已通过索引事务优化修复；若复现，检查 `logs/watch.log` 和索引进程 |
| 豆包看不到工具 | 连接器开关是否打开；URL 是否为 `http://127.0.0.1:8766/mcp`；服务是否运行；豆包“本地电脑”权限 |
| 菜单栏没有 `KB` 图标 | `kb tray --check`；缺 rumps 时 `pip install -e ".[tray]"`；看 `logs/tray.log` |
| pip 安装失败 | 检查网络/代理/PyPI 镜像；公司网络先配置 `HTTPS_PROXY` |
| 索引很慢 | 缩小范围，排除大目录；首次全盘建议夜间运行 |
| PDF/Word 没有正文 | 安装可选依赖：`pip install -e ".[docs]"` |
| 图片整理报缺少 OpenCV | `pip install -e ".[vision]"`，或 `kb setup --with-vision` |
| Ollama 未安装/模型没下载 | `kb model install --name qwen2.5:3b`；或 `kb setup --with-ollama` |
| 模型回答 500 / GGML 断言 | 把 `models.local.num_gpu` 设为 `0`，重启 Ollama |
| 脑图卡在"正在读取知识库索引" | ① 服务刚重启后的首次建图 1~2 分钟（有真实进度条）属正常，等它走完；② 服务没起：`lsof -nP -iTCP:8770 -sTCP:LISTEN` 应有 python 在监听，没有就 `kb stop; kb start`；③ 本机代理（ClashX 等）拦截了 127.0.0.1 → 给回环地址加绕过；④ 以上都排除后硬刷新（Cmd+Shift+R） |
| 浏览器打不开、终端 curl 正常 | 99% 是代理把 127.0.0.1 抓走了：ClashX 设置里给局域网/127.0.0.1 加绕过，或临时退出代理再试 |
| 整机发烫、风扇狂转 | 先看 `ps -Ao pid,pcpu,command -r \| head`：AI 客户端（多开会话每个常驻 15~30%）和嵌入补算是主要热源；补算已限 2 核 + 15 分钟节流，不用的 AI 窗口关掉 |
| 接口全卡但页面静态能开、进程 0% CPU | 服务假死：`kill -SIGUSR1 <map_pid>`（map 已注册 faulthandler）会在 `logs/map.log` 打出全部线程栈；然后 `kb stop; kb start` 恢复 |
| 顶栏"语义嵌入 %"和实际不符 | 该数字用 `MAX(id)` 估算（删过的文件会虚高分母），精确值以 `kb embed --stats` 为准 |
| 模型回答很慢 | CPU 推理正常；可换 `qwen2.5:1.5b` |
| 移动目录后启动失败 | 删除 `.venv`，重新运行 `bash install.sh` |

统一自检：

```bash
.venv/bin/python -m kb setup --check
```

## 8. 安全与数据

- 索引和文件内容默认都在本地；MCP 默认只听 `127.0.0.1`。
- MCP 没有内置鉴权；不要把 8766 直接暴露到公网或局域网。需要远程访问时自己做 HTTPS 隧道和 Token。

- 整理是写操作：先 `--plan` 预览，再 `--apply --yes`；默认不删除、不覆盖。
- `config/feishu.json`、`config/config.json` 含本地配置，已被 `.gitignore` 排除，不要提交。
- 分享前运行 `scripts/scan-secrets.sh`（或 `kb scan`），检查绝对路径、邮箱、手机号、密钥。

## 10. 图片整理（OpenCV）

### 安装

```bash
.venv/bin/python -m pip install -e ".[vision]"
```

或在交互式 `kb setup` 中选择安装 OpenCV；`install.sh` 也支持：

```bash
KB_WITH_VISION=1 bash install.sh
```

### 使用

```bash
# 1) 生成计划，只预览不移动
kb organize /path/to/photos --strategy image --plan

# 2) 确认后执行
kb organize /path/to/photos --apply <计划ID> --yes

# 3) 需要时撤销
kb organize /path/to/photos --undo <计划ID>
```

飞书私聊也可以：

```text
整理图片 /path/to/photos
确认整理 <计划ID>
撤销 <计划ID>
```

### 分类规则

OpenCV 会按画面特征粗分到：

| 分类 | 主要判断 |
|---|---|
| 人物 | 检测到人脸 |
| 文档截图 | 高亮度、低饱和、文字/线条边缘 |
| 风景 | 色彩饱和度高，或低亮度但有明显场景 |
| 其他 | 不符合以上特征 |

这是启发式分类，不保证语义准确。建议先 `--plan` 预览，再执行；默认不删除、不覆盖，重名自动加后缀。

### 限制

- 只处理常见图片格式：jpg/jpeg/png/bmp/webp/tif/tiff；HEIC/SVG 等可能归到“其他”。
- 只移动图片文件，目录里的非图片文件保持不动。
- 人脸检测使用 OpenCV 自带 Haar 模型，侧脸、遮挡、小脸可能识别不到。
- 图片内容不会上传；分类在本机完成。

## 11. 本地模型问答（Ollama）

### 两种模式

| 模式 | 行为 |
|---|---|
| `none`（默认） | 使用现有的搜索 + 摘录式回答，不依赖模型 |
| `ollama` | 先检索本地资料，再把资料交给本地 Ollama 模型分析并回答 |

搜索、找文件、发文件、总结目录、整理文件仍然走确定性规则；只有问答（`kb ask`、飞书里直接提问）使用模型。

### 安装与启用

```bash
# 查看状态
kb model status

# 安装 Ollama（如需要）并下载模型；3b 约 2GB
kb model install --name qwen2.5:3b

# 启用已安装的模型
kb model enable --name qwen2.5:3b

# 关闭模型，恢复摘录式
kb model disable
```

也可以交给 `kb setup`：

```bash
kb setup --with-ollama --ollama-model qwen2.5:3b
```

模型大小参考：

| 模型 | 体积 | 特点 |
|---|---|---|
| `qwen2.5:1.5b` | 约 1GB | 最快，质量一般 |
| `qwen2.5:3b` | 约 2GB | 速度和质量的平衡（推荐） |
| `qwen2.5:7b` | 约 4.7GB | 质量更好，CPU 上更慢 |

### 配置

`config/config.json`：

```json
{
  "models": {
    "mode": "ollama",
    "local": {
      "chat": "qwen2.5:3b",
      "num_gpu": 0
    }
  }
}
```

- `num_gpu`：`0` 表示只用 CPU。部分 macOS 13 + Apple Silicon 环境使用 Metal 会触发 `GGML_ASSERT(buf_dst)`，默认 CPU 更稳；如果你的机器 Metal 正常，可以改成较大的层数加速。
- 首次加载模型需要几秒到几十秒；CPU 上 3b 生成一段回答通常十几秒到几十秒。
- Ollama 服务没启动时，`kb ask` 会回退到摘录式，并在回答末尾提示；不会直接失败。
- `kb start` 在 `mode=ollama` 时会尝试启动 `ollama serve`，并在后台预热模型。

### 性能优化

`config/config.json` 的 `models.local` 已经带了偏速度的默认值：

| 参数 | 默认 | 作用 |
|---|---|---|
| `num_gpu` | `0` | GPU 卸载层数。**旧 macOS（13.x）Metal 有兼容 bug 必须 0**；macOS 14+/新机器设 `999` 走 GPU，速度从 ~7 tok/s 提到 40+ tok/s。崩溃报 `GGML_ASSERT(buf_dst)` 就改回 0 |
| `num_thread` | `8` | CPU 线程数，按机器核数调整 |
| `num_ctx` | `3072` | 上下文窗口；越大越慢、越占内存 |
| `num_predict` | `320` | 单次最多生成 token 数；限制长回答 |
| `keep_alive` | `24h` | 模型常驻，避免每条消息重新加载 |
| `context_chars` | `2500` | 送给模型的资料总长度 |
| `max_sources` | `3` | 最多送几个来源片段 |
| `cache_seconds` | `600` | 相同问题在常驻进程内缓存 10 分钟 |
| `answer_without_context` | `false` | 没有检索到资料时不调用模型，直接返回“未找到” |

实测（qwen2.5:3b，CPU）：

- 冷启动后第一次带资料回答约 20–25 秒；
- 模型已加载后约 6 秒；
- 相同问题命中缓存约 1 秒；
- 简单短回答约 5 秒。

飞书在模型模式下会先回一条“正在本地资料中查找并用模型分析，请稍候…”，然后发最终答案。

如果仍然觉得慢：

1. 换更小的模型：
   ```bash
   kb model install --name qwen2.5:1.5b
   kb model enable --name qwen2.5:1.5b
   ```
2. 降低 `num_predict`（例如 160）或 `context_chars`（例如 1500）。
3. 临时关闭模型：`kb model disable`，问答立即回到摘录式。

### 模型回答示例

```bash
kb ask "安装与使用文档里怎么启动服务"
```

返回会包含：

- `mode: ollama`、`model: qwen2.5:3b`
- 模型生成的结论和依据
- 来源文件列表（本地索引命中）

### 安装失败时

- macOS 13 上 `brew install ollama` 可能因 `mlx` 要求 macOS 14+ 失败。可以到 Ollama 官方 release 下载 `ollama-darwin.tgz`，解压后把 `ollama` 放到 `~/.local/bin` 或 `/usr/local/bin`。
- 模型下载失败：检查网络/代理；也可以先手动 `ollama pull qwen2.5:3b`。
- 模型返回 500 / `GGML_ASSERT`：把 `config/config.json` 的 `models.local.num_gpu` 设为 `0`，重启 Ollama 后重试。
- 不想用模型：`kb model disable` 或 `kb setup --no-ollama`。

### 隐私

模型在本机运行，资料不会因为问答发给云端；但如果你同时接了飞书/豆包，回答仍可能通过对应聊天工具外发，注意合规。

## 12. 3D 知识库脑图（`kb map`）

```bash
kb map --open
# http://127.0.0.1:8770/
```

功能：

- 索引数据以 3D 星空展示：拖拽旋转（松手带惯性）、滚轮缩放；每个类型星云缓慢自转，不再绕全局中心转
- 星点可以单独拖动，附近的点会被带着一起拉伸，像拉面条；松手后整片弹性回位，鼠标靠近时点和连线也会轻微跟随
- 不再提供手动视角按钮；空闲约 12 秒后镜头会自动缓慢俯仰（俯瞰/平视/仰望之间过渡），配合纵向高度和远近雾化形成层次
- 首次打开有进度条：读取索引库 → 打标签 → 布置星云 → 生成星点，完成自动消失
- 每个类型是一个独立星云岛，分布在外圈；文件点只在自己的星云里，扩展名/目录/项目/状态等二级标签挂在所属类型旁边；根节点用曲线连接各星云
- 点击类型星云会平滑放大进入该云团，其它云团淡出；滚轮放大到一定程度也会自动进入鼠标附近的云团；滚轮缩小到一定比例或点“返回全景”回到整个星系
- 各类型星云绕自己的中心缓慢自转，速度已调快（约 1 分钟一圈）
- 星点是空心圆圈包裹文字，远近有明暗层次；左上角小字显示最近一次系统自检
- 每个文件点默认在旁边标出文件名（自动避让重叠，放大/聚焦后会显示更多），悬浮可看完整路径
- 圆点内仍保留首字母/单字，选中时换成短词（如 `SET`、`安装`）；标签点内也显示单字/短词
- 顶部“清理空间”直接打开清理面板：显示可释放空间和重复/空/临时/缓存四类建议，可单组清理或一键清理列表内文件（移到废纸篓）；清理时显示加载条，完成后显示成功/失败数量
- 右上角“全屏”进入全屏（快捷键 `F`），顶部“助手”按钮可显示/隐藏聊天浮层
- 左侧是可拖动的知识库助手浮层：默认满高，拖标题移动，右下角拖动缩放，`设置` 改助手名字/说话风格，`清空` 清掉对话，`⇤` 固定到左侧栏/取消固定，`—` 收起，`×` 关闭；搜索和提问合并成一个输入框、一个“发送”按钮
- 助手默认叫“小助手”，第一次打开会提示设置名字和风格；回答保持简短、拟人化，不展示完整路径，文件结果只给简短路径和“复制路径”按钮，不再提供详情按钮
- AI 回答用打字机效果逐字输出，不会一次性刷出整段
- 气泡宽度按文字长度自适应，短句不会撑满整栏
  - 每条 AI 消息右上角有“收起 / 展开”，长回答和文件列表可以单独折叠；收起后内容在 96px 小窗里仍可上下滚动
  - 普通文件名/关键词：直接返回匹配文件列表，2 秒左右
  - 问题（带“怎么/什么/为什么/吗”等）：先出匹配文件，再调用 `kb ask` 给回答和引用来源
  - 输入“推荐删除”：列出重复/空/临时/缓存建议，可展开明细、单条删除、整组删除或一键删除列表中的文件
  - 输入“推荐整理”：列出适合整理的目录（按图片数/文件数排序，排除工具缓存目录），点“整理”直接带入整理面板
- 渲染做了限帧和缓存：交互时约 42fps，空闲降到约 22fps；暂停自动旋转且没有操作时完全不重绘，星云用预渲染贴图，减少显卡/CPU 占用
- 点击图中的文件节点，会在鼠标附近弹出可拖动的详情浮窗：路径、大小、状态、标签，以及“打开所在目录 / 复制路径 / 移到废纸篓”
- 右上角“整理”打开整理浮窗：打开后自动列出推荐文件夹，并按当前整理方式过滤（图片归类只显示有 3 张以上图片的目录，其它方式显示文件数 ≥20 的目录），点一行即可带入路径；再选方式（OpenCV 图片归类 / 类型 / 月份 / 内容）、是否递归，先出计划再执行，可撤销
- “更新索引”按钮手动执行一次 `kb index`，适合刚加完文件立刻刷新；它和 `kb watch` 用的是同一套索引逻辑，区别只是：watch 默认按文件事件实时增量，按钮是手动触发一次全量增量（只更新有变化的文件）。页面每 60 秒检查 `kb.db`，不管哪边更新都会自动刷新
- 删除只针对重复/空/临时文件，移到系统废纸篓，可从废纸篓恢复；缓存目录只给建议，不删除
- 默认展示 500 个代表文件；节点统计覆盖全部索引文件
- **语义连线**：内容相近的文件间画紫色细线（向量余弦 ≥0.80），知识"簇"肉眼可见；悬停文件时它的相似邻居会亮起
- **极简模式**（顶栏"极简"）：纯点+细环的 Obsidian graph 风格，偏好记忆
- **搜索淡出**：右上角搜索框输入时，非匹配节点压暗到 5%（对照 Obsidian graph 过滤）
- **档案卡**：点文件显示修改时间、正文预览、**语义相似文件 top5**（点击跳转）
- **局部视图**：档案卡"局部视图"按钮——只亮该文件的语义邻居和同目录文件（Esc 退出）
- **命令面板**：`Ctrl/⌘+P`——聚焦分类、视图切换、面板开关全键盘可达
- **时间着色**（顶栏按钮）：按修改时间给文件点上色（金=近7天/绿=30天/蓝=90天/靛=1年/灰=更早），看"最近活跃区"
- **生长动效**：新入库的文件节点以弹性动画"长"到球体上

参数：

```bash
kb map --port 8771 --max-files 800 --index-on-start --open
```

- `--max-files`：3D 图中最多展示多少个文件节点，越大越卡。
- `--index-on-start`：启动时触发一次增量索引。
- `--interval`：检查索引变化的秒数，默认 60。

停止：

```bash
kill "$(cat logs/map.pid)"     # 启动时会写入当前进程号，退出时自动删除
```
